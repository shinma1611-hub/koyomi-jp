# koyomi-jp

[English](README.en.md)

日本の暦を計算する、依存なしの小さな JavaScript ライブラリです。日付を渡すと、六曜、祝日、二十四節気、干支、一粒万倍日、天赦日、旧暦を返します。ネットワークにはつながず、端末の時間帯にも左右されません。

対応範囲は **2022年1月1日から2032年12月31日まで** です。

## 使い方

このフォルダをプロジェクトに置いて読み込みます（npm には公開していません）。

```js
// CommonJS
const koyomi = require("./koyomi-jp/koyomi.js");

const day = koyomi.info(2026, 11, 3);
console.log(day.rokuyo);  // "友引"
console.log(day.holiday); // "文化の日"
console.log(day.lunar);   // "9月24日"

// 2027年6月の土日祝で、大安の日を探す
const days = koyomi.month(2027, 6).filter(
  (x) => x.rokuyo === "大安" && (x.w === 0 || x.w === 6 || x.holiday)
);
console.log(days.map((x) => `${x.m}月${x.d}日`)); // [ "6月5日" ]
```

```js
// ES Modules
import { info, month } from "./koyomi-jp/koyomi.mjs";
```

```html
<!-- ブラウザ。window.Koyomi として使えます -->
<script src="koyomi.js"></script>
<script>console.log(Koyomi.info(2026, 1, 1).holiday);</script>
```

動く例は `examples/basic.js` にあります（`node examples/basic.js`）。

## API

| 名前 | 説明 |
|---|---|
| `info(年, 月, 日)` | 1日分の情報を返す。日付は日本の暦の日付として渡す |
| `month(年, 月)` | その月の全日分を配列で返す |
| `ROKUYO` | 六曜の配列。（旧暦の月＋日）を6で割った余りの順 |
| `MIN_YEAR` / `MAX_YEAR` | 対応する最初と最後の年（2022、2032） |

対応範囲の外の年と、存在しない日付（2月30日など）は `RangeError`、整数でない引数は `TypeError` になります。範囲外の値を黙って返すことはありません。

`info` の返す値は次のとおりです。

| 項目 | 内容 | 例 |
|---|---|---|
| `y` `m` `d` | 年、月、日 | `2026` `11` `3` |
| `week` / `w` | 曜日と、その番号（0が日曜） | `"火"` / `2` |
| `rokuyo` | 六曜 | `"友引"` |
| `holiday` | 祝日名。祝日でなければ `null` | `"文化の日"` |
| `sekki` | その日に始まる二十四節気。なければ `null` | `"立冬"` |
| `eto` | 日の干支 | `"辛巳"` |
| `ichiryu` | 一粒万倍日か | `false` |
| `tensha` | 天赦日か | `false` |
| `lunar` | 旧暦。閏月は「閏」が付く | `"9月24日"`、`"閏2月1日"` |

## 知っておいてほしいこと

### 六曜などは言い伝えです

六曜、一粒万倍日、天赦日は昔からの言い伝えで、**科学的な根拠はありません**。縁起の良い日に何かをしても、結果やお金の増え方が良くなることを示すものではありません。一粒万倍日と天赦日は、暦によって扱いが少し異なることがあります。

### 対応は2022〜2032年で、旧暦2033年問題があります

旧暦は、新月の日を1日とし、中気を含む月に番号を付けて作っています。ところが2033年秋から2034年春にかけては、この決まりだけでは月の番号が定まりません（**旧暦2033年問題**）。そのため、確かだと言い切れない年に入る前の2032年までに絞っています。2022年より前は比較の表がなく、2021年までの特例の祝日にも対応していないので、対象外です。

### 祝日の先の年は予測です

祝日は、現在の祝日法の決まりで計算しています。**法律の改正や特例は反映しません。** 春分の日と秋分の日は、正式には前の年の2月に発表されるので、この計算は先の年については予測です。予定を決めるときや、業務で使うときは、内閣府の発表で確かめてください。

### 節気の日付の精度

太陽の位置は簡易な計算式（精度はおよそ0.01度、時間にして約15分）で求めています。この誤差で日付が変わる次の3件は、精密な暦の値に合わせて補正しています。

| 節気 | 補正後の日 | 節気の瞬間（日本時間） | 根拠 |
|---|---|---|---|
| 小寒 | 2023年1月6日 | 0時05分 | 国立天文台 暦要項 |
| 夏至 | 2023年6月21日 | 23時58分 | 国立天文台 暦要項 |
| 立冬 | 2031年11月8日 | 0時05分ごろ | NASA JPL Horizons による計算 |

**2030年の雨水だけは、日付を言い切れません。** 計算上の瞬間は2月18日23時59分57秒で、午前0時まで約3秒です。この先の地球の自転のずれで前後するので、このライブラリの2月18日と公式の暦の日付が異なることがあります。

小寒、大雪、芒種、立冬などは月の区切りになるので、節気の日付は前後の一粒万倍日と天赦日にも影響します。

## 計算の方法

- **旧暦と六曜**：日本時間で新月になる日を1日とし、中気を含む月に番号を付けます。六曜は（旧暦の月＋日）を6で割った余りで決まります。
- **二十四節気**：太陽の黄経が15度ごとの境目を越える日です。
- **干支**：60日の周期で数えます。
- **一粒万倍日**：節気で区切った月と、日の十二支の組み合わせで決めます。
- **天赦日**：節気で区切った季節と、日の干支の組み合わせで決めます。

新月と太陽の位置は、Jean Meeus『Astronomical Algorithms』の計算法をもとにしています。

## テスト

```sh
npm test
```

依存はないので、インストールは要りません。Node.js 18 以上で動く想定です（確認したのは v24 だけです）。

テストでは `test/koyomi-golden.json` の2022〜2032年の全4018日と結果を比べます。この表は同じ計算法で書いた Python 版の出力に、上の3件の補正を加えたものです。写し間違いは見つけられますが、計算法そのものの誤りは見つけられません。

公式の資料などと照らし合わせたのは、次の範囲です。

- 節気：2026年と2027年の全48件が国立天文台の暦要項と同じ日付です。
- 節気：2022〜2032年で午前0時の前後およそ40分以内の節気を NASA JPL Horizons と比べました。そのうち暦要項が読める5件は、Horizons と暦要項の時刻が分まで一致しました。
- 六曜、旧暦、祝日などは全日を照らし合わせていません。正確さが必要な用途では、公式の資料で確かめてください。
